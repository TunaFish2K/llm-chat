# 加载与手动重试

启动时同时读取本机离线历史和服务端快照。本机已有内容可立即显示并编辑草稿；在线结果随后刷新。没有本机记录时显示页面骨架。缓存不是删除依据，只有在线清单或明确的会话不存在响应才能确认删除。

后台刷新失败保留已显示内容，并提供错误与重试入口。状态栏位于页面布局内，不能覆盖导航或输入控件。在线启动结果不能覆盖请求期间新增的会话、更新过的消息或正在编辑的草稿。切换服务实例或退出登录后，旧请求不能回填当前状态。

## 页面资源

`apps/web/src/lib/resource.ts` 按资源键共享读取、缓存、错误和刷新状态。同键并发请求合并；切换目标后读取独立记录；本地更新增加版本号，阻止较早的读取覆盖已保存修改。缓存只存在于内存，未使用记录在 10 分钟后可回收；达到 50 项时优先清理未使用且无请求的记录，正在使用的记录不强制淘汰。会话正文继续沿用当前会话及活动生成的保留规则。

| 页面 | 加载行为 |
| --- | --- |
| Agent 编辑 | 主体、工具目录和 Skill 独立读取；辅助资源失败仍可编辑主体；未保存修改不被后台刷新覆盖 |
| 设置 | 工具设置与目录分开；Skill、Plugin、MCP、记忆及容器资源保留上次成功结果 |
| 后台任务、轨迹、检查器 | 按会话或任务键复用结果；刷新和日志失败保留已有详情，提供重试 |
| 搜索 | 新查询取消旧请求；等待及失败期间保留旧结果，但旧查询的结果不可点击或回车选中 |
| 目录选择 | 取消前一次目录读取；输入路径与已加载目录不一致时，禁止确认旧目录 |

共用加载提示延迟 150 ms 显示，减少快速请求的闪烁。已显示的内容不会因刷新恢复成整页加载画面。

## 发送

离线标记不禁止编辑或点击发送。每次点击实际尝试请求；失败时显示错误并保留内容，只有用户手动重试才再次提交。没有离线发件箱，也不在恢复联网后自动补发。

发送总等待上限为 30 秒，覆盖 `before_send` 脚本、响应头及响应体。普通 JSON 读取上限为 15 秒，写入上限为 30 秒。收到服务端接收结果后立即结束发送等待，消息与会话列表在后台同步。草稿向服务端的同步不再挡住发送；输入框在请求期间仍可编辑，成功后只清理本次发送的文字和附件，保留后来输入的内容。上传仍使用独立的上传管理逻辑。

客户端在请求前将提交 ID、原始文字、脚本处理结果、附件 ID 和新会话参数保存到当前标签页的 `sessionStorage`。手动重试复用这份请求；刷新页面后也能恢复。记录按服务实例隔离，接收成功、会话删除、退出登录或切换实例时清理。存储不可用时只能在当前页面内保留重试记录。

## 服务端去重

数据库版本 47 增加 `client_submissions`。创建会话、发送消息、加入队列及受限脚本执行接受可选 UUID 字段 `clientSubmissionId`。旧客户端不传该字段时继续按原流程处理。

同一作用域和提交 ID 的首次业务写入与结果记录在一个 SQLite 事务内提交。相同请求再次到达时返回已保存结果；内容不同则返回 `409 submission_conflict`。受限脚本的状态修改和成功审计同样去重。消息结果恢复时可继续启动尚在排队的生成，不创建第二条消息。已经删除的会话不能通过旧结果重新创建。

提交结果持久保存，不随页面缓存的 10 分钟回收周期删除，保证服务重启后仍能识别手动重试。结果表会随成功提交增长；本次没有引入自动过期规则。

## 加载测量

基线为 `759a715`。两版均使用生产构建、相同依赖、相同已保存会话及消息，关闭 Service Worker。Playwright Chromium 使用 390×844 触摸视口、2 倍像素密度和 4 倍 CPU 降速。将启动接口响应固定延后 3 秒，每版新建浏览器上下文测量 5 次。

测量从页面导航开始，到历史消息存在且输入框可编辑为止。改造前中位数为 **3737 ms**，改造后为 **771 ms**；范围分别为 3697–3840 ms 和 726–797 ms。改造后首屏不再等待这次网络响应。此结果来自桌面模拟，不代表安卓 PWA 真机、软键盘或全部网络条件下的表现。

## 回归范围

单元测试覆盖缓存与网络返回顺序、刷新期间新增会话、资源去重及旧响应隔离、响应头/体超时、离线实际发送、发送期间继续编辑、刷新后的手动重试，以及服务端事务回滚、重启恢复与请求冲突。

`e2e/loading.spec.ts` 验证缓存先显示、辅助资源失败可编辑、离线标记下实际发送，以及服务端已接收但响应丢失后的刷新重试。配合离线历史、草稿导航、Agent 设置和目录选择测试，在 Chromium、Firefox、WebKit 与手机 Chromium 上回归。生产构建与浏览器测试必须串行，避免构建清理测试服务正在使用的文件。

类型检查、生产构建、前端测试时间预算及部署冒烟检查通过。最终完整单元测试为 1111 项通过、14 项按现有条件跳过；语句覆盖率 96%，分支覆盖率 90.22%。

四浏览器合计 85 个场景通过，3 项手机专用场景在桌面项目跳过。保留旧消息后，原聊天测试会同时找到错误提示与消息操作中的“重试”；测试已限定到对应错误提示，四浏览器重跑通过。手机离线回归还确认启动错误状态栏不会遮挡导航搜索。
