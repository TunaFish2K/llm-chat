# 国际化

Chat 的界面语言仅属于当前浏览器，不写入服务端设置。登录页和「设置 → 通用」都可选择简体中文、美式英语或跟随浏览器。自动模式按 `navigator.languages` 的顺序选择首个中文或英文，其他语言回退到美式英语。

偏好保存在 `llm-chat.locale.v1`。切换立即生效，不重建页面或清空表单；浏览器拒绝保存时，本次页面仍使用所选语言并显示提示。其他标签页会接收存储变更；自动模式响应浏览器语言变更。两套资源随应用打包并纳入离线缓存。

## 增加界面文字

1. 在 `packages/i18n/src/locales/zh-CN.json` 和 `en-US.json` 中增加同名语义键。动态值使用插值，数量变化使用 i18next 的 `count` 和复数形式。
2. React 组件调用 `useLocale()` 订阅语言变化，使用 `t(key, params)` 生成当前文字。不要在模块加载时缓存翻译后的标签；需要保存到状态的提示使用 `localized(key, params)`。
3. 错误状态使用 `useErrorState` 或 `displayError`，保留错误对象的元数据。日期和数字按当前语言调用 `Intl`。辅助技术标签也必须翻译。
4. 增加两种语言的行为测试，检查插值、回退、离线与表单状态保留。

语言名称使用自身语言显示。用户填写的名称、消息、模型输出、Skill 正文、插件文字和原始日志不自动翻译。内置工具及 Skill 的显示名称按稳定标识和来源匹配，第三方同名扩展不会套用内置翻译。模型可见的提示与工具参数定义不随界面语言改变。

## 错误和历史兼容

应用生成的错误可携带 `i18n: { key, params? }`，同时保留 `code`、`message` 和 HTTP 状态码。服务端用 `withMessage` 为错误附加元数据，API、生成事件与历史记录传递同一描述。客户端只翻译已知键；未知键、旧记录和外部错误显示原文。

数据库版本 41 为生成、图片生成、工具调用、识图、消息队列和后台任务增加可空的 `error_i18n_json`，不改写旧错误。版本 40 曾用于提交回执，升级保留该表。回滚需使用对应版本的完整数据备份。

新内置工具调用保存格式器名称和版本；浏览器用共享纯函数生成本地化说明，旧快照保留回退。具体边界见[工具展示协议](TOOL-PRESENTATION.md)。

## 通知和安装

页面将当前语言传给 Service Worker，并独立保存到通知数据库。语言变更不更改通知授权版本、已读记录或去重键，也不补发历史通知。已显示的通知不重发。

两个 `manifest.*.webmanifest` 使用相同的 `id`、`start_url` 和 `scope`，语言切换不会创建另一套应用身份。浏览器可能只在重新安装或更新安装信息时刷新已安装应用的说明。
