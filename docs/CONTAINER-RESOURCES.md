# 容器资源

在「设置 → 容器资源下载」选择节点，然后下载默认资源，也可等会话首次执行命令时自动下载。Alpine 基础包、运行组件和常用工具分别显示；每个资源的手动下载清单包含完整依赖。下载文件全局共用，安装结果按引擎和软件组合复用。

下载失败时先查看具体错误，再切换节点并点击「下载／重试」。网页提供各文件的当前节点链接。也可在网络方便的设备下载清单中的文件，通过网页多选上传。对于另一套已经下载完的应用，可以导出 `.llmresources` 离线包，再上传到目标应用。中断后重新选择同一文件即可续传；错误的版本、长度或校验值不会进入缓存。

Agent 执行设置选择 Alpine 后，可勾选需要预载的软件。必需组件始终安装，常用工具默认勾选，插件软件默认不勾选。保存 Agent 不启动容器。首次命令等待资源准备完成，进度显示在全局资源页面。修改已有会话的预载选项会切换环境，旧环境保留；有活动工具或后台任务时须先结束它们。

Alpine 使用 musl，依赖 glibc 的预编译程序需要另选兼容版本或继续使用已有 Debian 运行镜像。容器网络仍跟随宿主机，包括 localhost 和 TUN 路由。

## Plugin 软件声明

`plugin.json` 支持可选 `containerResources` 数组。每项包含：

| 字段 | 含义 |
| --- | --- |
| `id`、`name`、`version` | 插件内资源标识、显示名称和软件版本 |
| `description` | 可选说明 |
| `dependencies` | 依赖资源；插件内使用本地 ID，内置资源使用 `builtin:runtime` 等完整 ID |
| `variants` | `linux/amd64` 或 `linux/arm64`，发行版固定为 `alpine-3.24` |
| `variants[].files` | 全部所需文件：名称、大小、SHA-256、HTTPS 官方地址及可选清华／中科大地址 |
| `variants[].install` | 容器内的安装命令，文件位于只读 `/resources` |
| `variants[].verify` | 安装后的验证命令，失败时不保存共享镜像 |

软件文件名必须是单个文件名。APK 资源需要包含完整依赖，使用 `apk --no-network add /resources/*.apk` 安装；其他压缩包或二进制文件也可声明容器内安装步骤。安装步骤以容器 root 执行，并且不能使用网络。安装进系统目录；用户目录、工作区和运行状态不应成为共享软件的一部分。

插件资源在 Agent 配置中的完整 ID 是 `plugin:<plugin-id>:<resource-id>`。软件节点只能声明内置节点的对应地址；无适用镜像时使用资源的官方地址。仅提供软件的插件可省略 `entry`，安装插件只登记资源，不自动下载或预载。

资源版本更新应同时更新文件清单、校验值和验证步骤。已有会话保留固定的资源版本，新建或重置环境才使用新版本。导入插件离线文件前，先安装对应插件修订。

## 存储和升级

`dataDir/container-resources` 保存下载文件和未完成上传，数据库保存资源锁、任务和共享镜像引用。共享镜像和会话可写层位于对应容器引擎中。完整备份方法见[部署说明](DEPLOYMENT.md)。清理下载缓存会删除未完成上传，但不会移除已安装的软件；没有缓存也没有共享镜像的新环境需要重新下载或导入。

首版 amd64 在本次验证环境中的体积如下。下载量按文件去重；目录占用使用容器内 `du` 测量系统目录，不包含工作区、附件或后续安装的软件。

| 配置 | 下载量 | 容器内目录占用 |
| --- | ---: | ---: |
| Alpine 基础系统 | 3.7 MB | 10.1 MB |
| 基础系统 + 必需组件 | 35.0 MB | 87.6 MB |
| 基础系统 + 必需组件 + 常用工具 | 72.3 MB | 185.2 MB |

完整下载清单为 72,312,611 字节，基础包为 3,698,422 字节。Docker 在本机报告完整镜像约 74.5 MB，Podman 报告约 274.4 MB；这些镜像层统计不能直接当作容器内文件占用，也不能相减后当作可节省空间。文件、共享镜像层和会话可写层分别统计，具体磁盘占用取决于引擎及存储驱动。
