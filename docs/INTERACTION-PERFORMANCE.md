# 交互性能测量

优化覆盖会话树索引、侧栏虚拟列表、长历史虚拟渲染、最近会话缓存、离线索引 Worker，以及桌面侧栏和手机抽屉的即时反馈。主页面顶部不显示通信状态横幅。

## 测量方法

基线为 `2f19ba7`，使用独立检出的生产构建。本轮与基线均使用 Playwright Chromium、4 倍 CPU 降速和 1000 条包含 Markdown、代码及表格的消息。桌面视口为 1440×900，手机为 390×844、2 倍像素密度。关闭 Service Worker，每组执行 30 次展开和收起；以 CDP 输入触发实际鼠标或触摸事件。

帧间隔来自 requestAnimationFrame，慢帧指超过 33 ms 的间隔。点击反馈指标为 pointerdown 到第二次 requestAnimationFrame 的时间上界，不是硬件屏幕的实际出光时间。主线程长任务来自 PerformanceObserver，统计展开和收起的完整测量窗口；窗口含自动化检查及后台工作。前两次操作另存 CPU profile、合成器 trace 和截图，限制轨迹体积。

## 回归与限制

导航修复新增实际会话行点击测量：每组执行 30 次短、长会话之间的切换，计时到目标页面和可编辑输入框完成绘制，P95 必须低于 100 ms。1000 条历史仅挂载视口及邻近行，不逐批展开全量消息。诊断轨迹在两轮预热中采集，正式计时不包含 CPU profiler 的开销。原结果表记录上一轮抽屉展开与收起，不代表实际会话切换延迟。

2026-10-01 的缓存与重试修复将长历史的虚拟列表、边距测量和标题栏工具挂载延后到页面首帧之后；输入工具栏直接使用 ResizeObserver 通知中的尺寸，避免挂载时同步读取布局。标题栏为工具预留宽度，支持调度器的浏览器优先提交用户导航。以下为同一次完整复测，仍使用 1000 条消息、4 倍 CPU 降速和每组 30 次实际会话切换：

| 环境 | 会话数 | 点击反馈 P95 | 会话进入 P95 | 帧间隔 P95 | 慢帧比例 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 桌面 | 50 | 61.7 ms | 70.3 ms | 33.3 ms | 7.14% |
| 桌面 | 500 | 58.5 ms | 69.5 ms | 33.3 ms | 6.51% |
| 桌面 | 2000 | 64.5 ms | 69.1 ms | 33.3 ms | 7.24% |
| 手机模拟 | 50 | 35.8 ms | 97.1 ms | 16.8 ms | 2.60% |
| 手机模拟 | 500 | 36.5 ms | 91.0 ms | 16.8 ms | 2.86% |
| 手机模拟 | 2000 | 37.4 ms | 99.2 ms | 16.8 ms | 2.97% |

六组均通过原有的 100 ms 点击及会话进入门槛，通知先于发送响应到达的两组测试也通过。慢帧比例仍未达到 1% 目标；此前复测的手机会话进入曾出现 100 至 107.5 ms，因此保留分阶段计时和原门槛，继续监测主线程与调度波动，不能报告为全场景稳定 60fps。

`e2e/navigation-stability.spec.ts` 验证不完整缓存、相互指向的分支信息和后台通知下连续选择 100 次，最终页面及草稿保持最后一次选择；离开新会话又返回后，旧提交的迟到确认不能跳转或覆盖输入。变高消息测试检查千条历史的开头、末尾、有限 DOM 和底部跟随。

`e2e/interaction-performance.spec.ts` 保存上述测量产物，并限制点击反馈 P95 低于 100 ms。它还将消息读取延后 3 秒，检查切到短会话和返回长会话时，响应返回前即可继续输入并显示缓存；迟到的旧读取不能改变当前路由。新会话测试延后 HTTP 响应，验证通知先到时可以进入正式会话并保留后续草稿。

虚拟列表采用固定行高后，本轮三个规模的桌面和手机切换测试均通过。与加载和离线历史测试合并，在四浏览器项目中共 38 项通过，6 项依赖 Chromium 轨迹的测试在其他浏览器跳过。顶部横幅回归同时检查后台启动响应到达前后，聊天标题与输入框的位置保持一致。新会话确认还同时延后发送响应和消息读取，验证事件中的正式消息在跳转前不会被缓存回收。

测试机使用无头浏览器的软件合成路径，宿主机有其他用户程序运行；这会影响帧间隔，结果不能直接换算为 Android GPU 帧率。本轮没有连接 Android 真机，尚未验证 OnePlus Ace 5 的 Chrome PWA/APK、软键盘、发热、耗电和持续运行表现。真实稳定 60fps 仍需真机轨迹确认。

浏览器测试、生产构建和部署冒烟检查串行运行，避免构建清理 dist 导致服务短暂缺少静态文件。WebKit 通过官方 Playwright 容器中的浏览器服务运行，应用及数据库运行在宿主机。

## 少量重消息

2026-10-01 只读检查生产环境中的两条长会话后，发现此前 1000 条普通消息测试没有覆盖的缺口：12 条以内的消息直接全量渲染，关闭的推理和工具详情仍挂载。前者有 12 条消息、29 次活动工具调用、60857 字符推理和 39228 字符工具输出；后者有 10 条消息、28 次活动工具调用和 70917 字符工具输出。

所有非空历史现均按视口渲染。折叠的详情首次展开才挂载，再次关闭保留局部状态；同一工具调用与语言复用格式化结果。手机切换时，新富文本挂载等待抽屉退出完成，目标页面、可编辑输入框和网络读取并行推进。

`e2e/heavy-history.ts` 使用匿名内容匹配上述消息、活动工具调用、推理和工具输出规模，不保存生产会话内容。`e2e/heavy-conversations.spec.ts` 检查视口 DOM、开头与最新消息、详情首次展开、原始模式保留，以及未返回的消息读取不会阻止缓存与输入。移动性能检查对每组执行 30 次实际触摸切换，保持 4 倍 CPU 降速，要求点击和页面可输入 P95 均低于 100 ms，退出期间不提前挂载新正文，且没有超过 50 ms 的主线程任务。

发布构建复测如下，匿名夹具的推理与工具输出已匹配上述精确字符规模。

| 匿名会话形态 | 点击反馈 P95 | 页面可输入 P95 | 退出帧间隔 P95 | 退出长任务 |

| 工作目录、12 条消息 | 32.7 ms | 85.6 ms | 33.3 ms | 0 |
| 搜索、10 条消息 | 34.0 ms | 79.5 ms | 33.3 ms | 0 |

这组帧间隔仍未达到稳定 60fps。没有连接 Android 真机，不将桌面 CPU 降速模拟报告为 OnePlus Ace 5 的实测结果。
