# Chat

[English](README.en.md)

## 介绍

Chat 是单用户、自托管的 Web AI 聊天客户端。项目目录名为 `llm-chat`。浏览器显示消息和实时事件，服务端保存聊天、Agent、模型配置、密钥、附件和任务。

- 连接 OpenAI Responses、Chat Completions 和 Anthropic Messages 兼容接口。支持预置服务商、自定义地址和秘密请求头。
- 流式显示正文、推理摘要、工具调用和用量。消息支持 Markdown、表格、数学公式和受限 HTML。
- 上传图片和文件。支持 Responses 直接对话生图，也支持让聊天模型调用独立的图片生成工具。
- 配置 Agent、角色卡、上下文策略、备用识图模型、工具权限和 Skills。支持 Character Card V2 JSON 与 PNG 导入导出。
- 使用搜索、网页读取、记忆、文件、Shell、后台任务、MCP 和 Plugin 工具。Agent 可以通过 Codex app-server 委派编码任务。
- 保存回复版本和会话分支。编辑历史消息或从历史回复继续会创建分支。
- 在生成期间提交多条待发送消息。队列保存在服务端，可以删除单条或全部。
- 使用桌面和手机界面，也可以安装为 PWA。换设备后恢复服务端保存的分支选择和聊天状态。

应用使用 SQLite，不需要外部数据库。当前版本不提供多用户隔离。

## 如何部署使用

### 环境与启动

需要 Node.js 24 或更高版本，以及 pnpm 11.7.0。

1. 克隆仓库。

   ```bash
   git clone https://github.com/TunaFish2K/llm-chat.git
   ```

2. 进入项目目录。

   ```bash
   cd llm-chat
   ```

3. 安装依赖。

   ```bash
   pnpm install --frozen-lockfile
   ```

4. 构建应用。

   ```bash
   pnpm build
   ```

5. 启动服务。

   ```bash
   pnpm start
   ```

6. 打开 `http://127.0.0.1:3000`，使用首次启动时终端显示的八位初始密码登录。

首次启动会创建权限为 `0600` 的 `config.json`。默认只监听本机。需要独立配置文件时，执行 `pnpm start --config /etc/llm-chat/config.json`。该路径的父目录必须已存在。

| 配置项 | 默认值 | 用途 |
| --- | --- | --- |
| `host` | `127.0.0.1` | 监听地址 |
| `port` | `3000` | HTTP 端口 |
| `dataDir` | `./data` | 数据目录，相对路径以配置文件目录为准 |
| `authMode` | `password` | 远程访问必须使用密码认证 |
| `trustProxy` | `false` | 只在可信反向代理后配置代理信任 |
| `serveWeb` | `true` | 同时提供构建后的 Web 页面 |
| `shutdownTimeoutMs` | `30000` | 关闭期限，单位毫秒 |
| `buildId` | `development` | 日志和探针中的发布标识 |

远程部署需要修改监听地址。HTTP 会明文传输密码和会话，建议通过可信反向代理提供 HTTPS。PWA 安装和更新需要浏览器支持的安全上下文。不要将 `authMode: "disabled"` 的服务公开。

进程管理、反向代理、探针和密码恢复见[部署运维手册](docs/DEPLOYMENT.md)。

### 配置模型和 Agent

1. 在“设置 → 连接与模型”中添加连接。
2. 选择服务商并填写 API Key。自定义服务需要填写地址和协议。
3. 发现或添加模型，并核对模型能力。目录匹配会补全上下文窗口等参数，手动修改后停止自动覆盖。
4. 在“Agent”中为默认助手选择模型。
5. 新建会话并发送消息。

Agent 保存可复用的角色和执行策略。会话可以切换 Agent，也可以覆盖模型和推理档位。切换 Agent 会清除会话执行覆盖项。每次生成保存配置快照，后续修改不会改写历史回复。

### 搜索与图片生成

“设置 → 搜索引擎”统一配置 SearXNG 和 Tavily，可以同时启用。SearXNG 需要服务地址和 JSON 搜索接口。Tavily 需要 API Key，地址留空时使用官方默认地址。旧 Agent 搜索配置会迁移到全局列表，未选用的密钥保留为禁用项。

“设置 → 图片生成”管理图片工具可用的模型。先在“连接与模型”中启用模型的图片输出能力，并配置图片协议。上下移动列表项会保存推荐顺序。两份列表都允许 AI 选择其他已启用项，未指定时使用首个可用项。

Agent 的工具页仍管理启用状态和审批策略。AI 可用 `search_web({"action":"list_engines"})` 查询搜索引擎，再传入 `query` 和可选的 `engine_id` 搜索。

AI 可用 `image_generate({"action":"list_models"})` 查询图片模型，再传入 `prompt` 和可选的 `model_id` 生成图片。模型标识形如 `openai/gpt-image-2`，以实际返回值为准。重名会得到不同标识，改名和排序不会改变已有标识。

直接把图片模型作为 Responses 对话模型也受支持。此路径需要图片输出能力，不受图片工具列表开关影响。

### 分叉、队列与附件

生成中短按发送会加入普通队列。长按发送按钮约半秒，或在电脑上长按 Enter，可以使用 Steer。当前请求和工具完成后，Steer 在下一次模型请求前优先发送。它不打断工具，也不跳过审批。两类待发送消息都可以删除。

输入栏左侧的低频设置菜单包含工作目录和高级执行设置。窄屏空间不足时，Agent 也收入该菜单；模型和思考等级优先保留。右侧保留附件、发送和停止。聊天顶部的会话操作菜单提供压缩上下文和角色相关操作。

编辑历史消息及附件，或选择“从此处继续”，会创建分叉。撤回、重做和恢复记录功能已退役。旧版隐藏消息仍保存在数据库中，不自动放回聊天或模型上下文。旧暂停队列可以点击“继续发送”恢复。

上下文图片数量超过 Agent 的限制时，服务端可将较旧图片替换为缓存的文字说明。图片原件仍保留，识图说明不会替换消息附件。

### 可选工具

`browser_fetch` 使用无头 Firefox 读取执行 JavaScript 后的网页，不需要图形桌面。以服务运行用户安装浏览器：

```bash
pnpm --filter @llm-chat/server exec playwright-core install firefox
```

然后在 Agent 工具页启用浏览器读取。该工具不保留登录状态，不处理验证码，也不能保证绕过网站拦截。

Codex 集成通过 app-server 管理 thread、任务、审批和中断。默认使用 `server-workspace` 策略。`LLM_CHAT_CODEX_BIN` 和 `LLM_CHAT_CODEX_SOCKET` 可以指定程序与已有 socket。仅在服务端设置 `LLM_CHAT_CODEX_PROFILE=trusted-local-yolo` 时，才能使用对应的宽松策略。

服务启动时会发现当前用户 `~/.agents/skills` 的直接子目录。Agent 按需加载已启用 Skill。Plugin 是可信本地代码，子进程不提供主机权限隔离。文件和 Shell 工具使用生成快照中的会话工作目录。

### 更新与备份

应用打开且联网时，默认在当前浏览器同步全部会话的文字、生成版本、分支和图片。完成首次同步后，断网仍可打开、刷新和搜索已保存的记录；发送、重试和修改服务端设置需要联网。普通附件只保存文件信息，下载仍需联网。“设置 → 通用 → 离线记录”显示同步进度、时间和占用空间，也可清除记录并关闭自动保存。退出登录会清除本机记录。离线冷启动需要 HTTPS 或 localhost 及支持 Service Worker 的浏览器；浏览器清理站点数据后需要重新同步。

首次打开会显示可跳过的快速教程。“设置 → 通用”可以重放教程。是否看过只保存在当前浏览器的 localStorage，不同步到其他设备。聊天与认证信息仍由服务端保存。

通用设置支持预置强调色、HSV 自定义颜色和深色纯黑背景。蓝色预置为 `#018EEE`。支持振动的浏览器会在流式内容变化后防抖 50ms，再请求一次 8ms 短振动。

“设置 → 通用 → 聊天排版”可以调整字号、字间距和行间距，并即时预览。聊天输入栏的更多设置也提供同一组控件，以悬浮面板显示；拖动时聊天内容和输入文字立即更新，保存后同步到其他设备。支持恢复默认值。生成时，停止按钮独立显示在输入框右上角，附件与发送按钮保持原位。

“设置 → 通用 → 应用更新”检查当前设备的前端版本。准备好后点击“更新并刷新”。此操作不拉取源码，也不更新服务端。

服务端更新需要重新安装依赖、构建并重启。每个数据目录只允许一个服务进程。更新前停止服务并备份完整 `dataDir`、配置文件和进程管理配置。不要只复制 SQLite 文件，也不要混合新旧数据目录。

数据库迁移向前执行。旧程序可能无法读取新架构，回滚时需要匹配的发布版本与完整备份。密钥保存在服务端数据库中，备份也需要按密钥材料保护。

## 如何开发

安装依赖后运行：

```bash
pnpm dev
```

Web 地址为 `http://127.0.0.1:5173`，API 地址为 `http://127.0.0.1:3000`。Vite 将 `/api` 请求代理到服务端。浏览器不直接请求模型服务商。

| 目录 | 内容 |
| --- | --- |
| `apps/server` | Fastify API、SQLite、生成调度和工具 |
| `apps/web` | React 界面和原生 CSS |
| `packages/contracts` | 共享 Zod 契约与类型 |
| `packages/providers` | 模型协议适配器 |
| `e2e` | 隔离服务与浏览器回归测试 |

`pnpm check` 依次执行类型检查、Web 测试预算、生产构建和覆盖率测试。其他检查可以单独运行：

```bash
pnpm test
pnpm audit --prod
pnpm test:deploy
pnpm exec playwright install --with-deps chromium firefox webkit
pnpm test:e2e
```

部署测试依赖构建产物。浏览器测试使用独立临时数据目录，不连接生产数据。领域术语见 [CONTEXT.md](CONTEXT.md)。
